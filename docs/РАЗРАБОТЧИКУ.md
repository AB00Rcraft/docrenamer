## 1. Быстрый старт

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]" -r requirements-dev.txt

.venv/bin/python -m pytest tests -q            # весь набор
.venv/bin/python -m pytest -m safety           # инварианты файловой системы
.venv/bin/python -m pytest -m offline          # работа без сети
```

Перед тем как считать работу законченной (правило 15 `AGENTS.md`):

```bash
pytest tests/unit tests/integration tests/safety
python -m docrenamer.security.offline_guard --audit src/docrenamer
ruff check src tests
mypy
```

> Аудит офлайн-режима нацелен на `src/docrenamer` — программу, которая читает
> документы. Пакет `src/docrenamer_updater` знает про сеть по назначению, и
> `--audit src` покажет его как нарушение.

Запуск из исходников:

```bash
.venv/bin/python -m docrenamer "путь/к/папке" --dry-run   # CLI
.venv/bin/python -m docrenamer --gui                      # окно
```

## 2. Инварианты

Эти свойства не меняются ни от обновления библиотек, ни от продуктовых
пожеланий. Каждое держится не обещанием в документации, а кодом и тестом.

| Инвариант | Чем обеспечен | Чем проверен |
|---|---|---|
| Содержимое файла не меняется | ни один reader не открывает файл на запись; SHA-256 до и после | `tests/safety/test_no_mutation.py` |
| Нет перезаписи | `naming/collision.py` + проверка отсутствия цели прямо перед `Path.rename` | `tests/safety/test_rename_transaction.py` |
| Нет удаления | `unlink`/`rmtree` разрешены только в `security/temp_cleanup.py` внутри `runtime_temp/` | `tests/safety/test_temp_guard.py`, `test_source_audit.py` |
| Нет перемещения | `operations/safety.check_same_directory` | `tests/safety/test_rename_transaction.py` |
| Предпросмотр по умолчанию | `dry_run_default = true`; APPLY принимает только утверждённый план | `tests/integration/test_cli.py` |
| Отмена | manifest пишется инкрементально, `--undo` работает по нему | `tests/integration/test_full_cycle.py` |
| Офлайн | архитектурный запрет сетевых импортов + аудит | `tests/safety/test_source_audit.py`, `test_offline_runtime.py` |
| Русский язык — основной | единый конвейер декодирования, `TextQualityValidator` | `tests/safety/test_russian_release_gate.py` |
| В имя попадает только подтверждённое | `Field` без `evidence` не принимается | `tests/unit/test_ai.py`, `test_name_review.py` |

Единственное исключение из «файл не меняется» — `operations/scrub.py`: снятие
метаданных по прямой команде человека, по умолчанию в копию, с отчётом
`logs/scrub-*.json`.

## 3. Слои и поток данных

```text
cli.py / gui.py            тонкие оболочки: разбирают команду, показывают итог
        │
        ▼
app.py  Application        оркестратор: scan → analyze → preview → apply → undo
        │
        ├── scanner.py           обход каталога, ignore-шаблоны, защита от петель
        ├── file_signature.py    реальный тип по сигнатуре, сверка с расширением
        ├── technical.py         служебные файлы: узнать и не тронуть
        ├── analysis.py Pipeline разбор одного файла
        │     ├── readers/*        текст и метаданные (недоверенный вход)
        │     ├── metadata/*       exiftool, ffprobe и запасные пути на Python
        │     ├── ocr/*            выбор страниц + Tesseract
        │     ├── extractors/*     даты, ФИО, организации, номера, суммы, серии
        │     ├── ai/*             контекст → llama-cli → JSON → валидация
        │     └── naming/*         builder → review → sanitizer → collision
        ├── operations/planner.py план: что и во что переименовать
        ├── operations/rename.py  транзакция переименования
        ├── logging/*             журнал и manifest
        └── operations/undo.py    откат по manifest
```

Порядок «от дешёвого к дорогому»: метаданные → правила → чтение документа →
OCR → локальная модель. Модель не запускается, если имя уже собирается с
достаточной уверенностью (`ai/enricher.AIEnricher.needed`).

Разбор одного файла (`analysis.Pipeline.analyze`) по шагам:

1. `detect_type` — реальный тип по сигнатуре; расхождение с расширением даёт
   `EXTENSION_MISMATCH` (расширение при этом не меняется);
2. `classify_technical` — служебный файл сразу отбрасывается со статусом
   `TECHNICAL_FILE`;
3. проверка предельного размера (`LIMIT_EXCEEDED`);
4. reader по типу, иначе по категории (`reader_for`), иначе
   `UNSUPPORTED_FORMAT`;
5. `enrich` — детерминированные extractors, затем при необходимости модель;
6. `finalize` — уверенность, построение имени, самопроверка имени.

`Pipeline.postprocess` работает уже над списком результатов: там определяются
серии томов, пачки сканов и общие факты соседних файлов.

## 4. Модель данных

`types.py` — единственное место, где живут общие типы.

```python
Field(value=..., source=Source.TEXT, evidence="ПОСТАНОВЛЕНИЕ", confidence=0.96)
```

| Тип | Что описывает |
|---|---|
| `Field` | значение с обязательным происхождением и подтверждением; `accepted` — прошло ли оно проверку |
| `Source` | откуда значение: `TEXT`, `METADATA`, `REGEX`, `LLM`, `FILESYSTEM` |
| `EntityRef` | лицо или организация с ролью в документе |
| `Candidate` | кандидат от детерминированного extractor: значение, позиция, контекст |
| `ReadResult` | итог reader: текст, кодировка, качество текста, метаданные, статусы |
| `ScannedFile` | файл, найденный сканером: путь, размер, время, расширение |
| `FileAnalysis` | полный разбор файла: тип, категория, все `Field`, метаданные, статусы |
| `PlanItem` | строка плана: исходный путь, целевой, SHA-256, размер, время, уверенность, отметка |
| `RenamePlan` | план по каталогу: корень, строки, счётчики, сохранение в JSON |
| `RenameRecord` | запись о выполненной операции для manifest и отката |
| `Status` | единый словарь кодов состояния (см. [раздел 12](#12-коды-состояния)) |

Правило, которое держит всю конструкцию: **в имя файла попадает только то, у
чего есть `evidence`**. `Field` без подтверждения не принимается, и никакой
модуль не имеет права обойти это.

## 5. Карта модулей

### Корень пакета

| Модуль | Ответственность |
|---|---|
| `app.py` | `Application` — единая точка входа бизнес-логики: `scan`, `analyze`, `preview`, `apply`, `reanalyze`, `scrub`, `forensic`, `undo`, отмена работы, обслуживание при старте |
| `cli.py` | разбор аргументов (раздел 7 ТЗ), пошаговый диалог `--wizard`, диалог отката |
| `gui.py` | окно на Tkinter + ttk: главное окно, окно выбора папки, объединение страниц, настройки, подсказки, полоса хода работы |
| `config.py` | чтение и проверка `config.json`, атомарная запись служебного JSON, словарь видов документов |
| `paths.py` | portable-раскладка: где `runtime`, `models`, `logs`, `manifests`, поиск локальных бинарников |
| `scanner.py` | обход каталога, ignore-шаблоны, защита от петель и выхода за пределы дерева, подкаталоги для переименования |
| `file_signature.py` | реальный тип файла по сигнатуре, сверка с расширением |
| `analysis.py` | конвейер разбора, подсчёт уверенности, сборка анализатора |
| `types.py` | общие типы и словарь кодов состояния |
| `encoding.py` | определение кодировки: BOM → объявление → строгий UTF-8 → `charset-normalizer` → русские legacy-кодировки |
| `textquality.py` | оценка качества текста, распознавание «кракозябр», ключ сравнения `е/ё` |
| `technical.py` | служебные и системные файлы: распознать и не трогать |
| `history.py` | что программа переименовывала раньше — по manifest прошлых сессий |
| `learning.py` | обезличенный журнал: где алгоритм имён ошибается; отчёт для отправки |
| `presentation.py` | форматирование строк для интерфейса — без зависимости от Tkinter |
| `preview.py` | предпросмотр файла: миниатюра, начало текста, карточка сведений |
| `browsing.py` | что лежит в папке — для окна выбора папки; тоже без Tkinter |
| `reveal.py` | команда, открывающая проводник системы на нужном файле |
| `console.py` | UTF-8 в консоли, видимая замена непечатаемого |
| `selftest.py` | самопроверка комплекта: OCR, модель, ExifTool, ffprobe, 7-Zip, разбор пробного документа |

Три модуля — `presentation.py`, `preview.py`, `browsing.py` — намеренно не
зависят от Tkinter. Логика окна живёт в них и проверяется тестами там, где
графической подсистемы нет.

### `readers/` — чтение файлов

Недоверенный вход. Каждый reader возвращает `ReadResult` и **никогда** не
открывает файл на запись.

| Reader | Формат | Backend |
|---|---|---|
| `pdf_reader` | PDF | pypdf, pypdfium2 для рендера, OCR при плохом текстовом слое |
| `docx_reader` | DOCX | python-docx |
| `xlsx_reader` | XLSX, XLSM | openpyxl, только чтение, макросы не исполняются |
| `xls_reader` | XLS | xlrd |
| `pptx_reader` | PPTX | python-pptx |
| `text_reader` | TXT, MD, CSV, LOG, RTF | stdlib + `encoding.py` |
| `html_reader` | HTML, HTM | BeautifulSoup, JS не исполняется |
| `xml_reader` | XML, KML, KMZ, GPX | defusedxml, без внешних сущностей |
| `json_reader` | JSON | stdlib, с ограничением размера и глубины |
| `image_reader` | JPG, PNG, TIFF, HEIC, WEBP, AVIF, BMP, GIF, DNG, RAW | Pillow, pillow-heif, ExifTool или `pillow_exif` |
| `media_reader` | видео и аудио | ffprobe, mutagen, `mp4_atoms` как запасной путь |
| `eml_reader` | EML | stdlib `email` |
| `msg_reader` | MSG | extract-msg |
| `archive_reader` | ZIP, 7Z, RAR, TAR, GZ | stdlib и 7-Zip CLI, **только список** |
| `legacy_ole_reader` | DOC, PPT | olefile, свойства документа → `PARTIAL_SUPPORT_LEGACY_OFFICE` |

`readers/base.py` даёт общее: нормализация текста (NFC), лимиты объёма,
подсказка о языке, перенос сведений о декодировании, фильтр метаданных.

### `metadata/`, `ocr/`

| Модуль | Что делает |
|---|---|
| `metadata/exiftool.py` | опрос локального ExifTool (`-json -G -n`), только чтение |
| `metadata/ffprobe.py` | метаданные видео и аудио через локальный ffprobe |
| `metadata/pillow_exif.py` | запасной путь без ExifTool: дата съёмки, устройство, GPS, размеры |
| `metadata/mp4_atoms.py` | разбор боксов MP4/MOV без ffprobe, со счётчиком против «бомб» |
| `ocr/engine.py` | Tesseract: распознавание изображения и страниц PDF |
| `ocr/page_selector.py` | какие страницы распознавать: первые, последние, в пределах лимита |

Формат результата у запасных backend'ов совпадает с основным, поэтому reader
не различает источники.

### `extractors/` — детерминированные факты

| Модуль | Что извлекает |
|---|---|
| `dates.py` | даты, включая русские написания («18 августа 2026 г.»); выбор даты документа по приоритетам |
| `persons.py` | ФИО в разных формах и падежах; `person_key` сводит падежные формы одного человека, `nominative_rank` выбирает из найденных форм именительный падеж |
| `organizations.py` | организации и государственные органы |
| `identifiers.py` | номера документов, дел, исполнительных производств, ИНН и ОГРН с проверкой контрольных сумм |
| `amounts.py` | денежные суммы |
| `document_types.py` | вид документа по словарю маркеров `config/document_types.json` |
| `series.py` | тома и части одного документа, пачки подряд отснятых страниц |
| `common.py` | окно контекста вокруг найденного (это и есть evidence), надбавка за близость к началу |

### `ai/` — локальная модель

| Модуль | Что делает |
|---|---|
| `base.py` | контракт `LocalModel`: `available`, `info`, `generate` |
| `llama_cli.py` | запуск локального `llama-cli` списком аргументов, без сервера и без сети |
| `context_builder.py` | компактный INPUT: имя, тип, метаданные, заголовок, кандидаты, фрагменты |
| `prompt.py` | системный промпт на русском: запрет выдумывать, требование evidence, только JSON |
| `validator.py` | разбор JSON, проверка схемы, отбрасывание неизвестных полей и значений без подтверждения |
| `enricher.py` | нужна ли модель вообще и что из её ответа принять |

### `naming/` — построение имени

| Модуль | Что делает |
|---|---|
| `builder.py` | сегменты имени по категории файла, сохранение осмысленного имени, компактная запись ФИО и организаций |
| `review.py` | второй проход: независимая перечитка готового имени |
| `sanitizer.py` | запрещённые символы, зарезервированные имена Windows, длина, сборка имени из сегментов |
| `collision.py` | свободное имя при занятой цели: `имя__02`, `имя__03` |
| `dates.py` | формат даты в имени и все написания, по которым её можно узнать |

### `operations/` — всё, что трогает диск

| Модуль | Что делает |
|---|---|
| `planner.py` | построение плана, повторная проверка строки перед APPLY, ручное имя, объединение страниц |
| `rename.py` | транзакция переименования файла и папки |
| `safety.py` | проверки: длина пути, та же папка, источник готов, цель свободна, имя допустимо, каталог доступен на запись, файл не изменился |
| `hashing.py` | SHA-256 файла и дешёвая подпись `(size, mtime)` |
| `undo.py` | откат сессии по manifest в обратном порядке |
| `scrub.py` | снятие метаданных — единственная операция, меняющая файл |

Транзакция переименования (`rename_file`) выполняет десять шагов раздела 48
ТЗ: проверки → SHA-256 до → `Path.rename` → проверка появления цели → SHA-256
после → сверка → запись в manifest. Несовпадение сумм даёт
`CRITICAL_HASH_MISMATCH` и прекращает автоматическую серию.

### `logging/`, `security/`

| Модуль | Что делает |
|---|---|
| `logging/text_log.py` | человекочитаемый журнал запуска в UTF-8 |
| `logging/manifest.py` | инкрементальная запись manifest, восстановление после сбоя, поиск незавершённых сессий |
| `security/offline_guard.py` | аудит исходников на сетевые импорты и URL; проверка, что сетевые модули не загружены в процесс |
| `security/subprocess_safe.py` | запуск локальных инструментов: список аргументов, `shell=False`, timeout, без консольного окна |
| `security/limits.py` | лимиты обработки недоверенного входа |
| `security/temp_cleanup.py` | временные данные сессии строго внутри `runtime_temp/`, уборка брошенных сессий |

### `docrenamer_updater/` — отдельная программа

Единственный пакет, который знает про сеть, и единственный, который никогда не
открывает пользовательские файлы. Скачивает установщик, сверяет SHA-256 по
опубликованному `SHA256SUMS.txt`, запускает. Отдельный тест следит за тем,
чтобы `docrenamer` его не импортировал.

## 5A. Оформление окон и кнопок

Разнобой в окнах читается как небрежность: у одного окна есть шапка, у другого
нет, кнопки разной ширины, главное действие то слева, то справа. Поэтому у
окон один каркас, и новые окна собираются из тех же трёх частей.

### Каркас окна

```text
┌──────────────────────────────────────────────┐
│ Ренеймер документов — выбор папки            │  системный заголовок, тёмный
├──────────────────────────────────────────────┤
│ Выберите папку с документами                 │  dialog_header(): название
│ Слева — папки, справа — что в ней лежит.     │  и пояснение
│──────────────────────────────────────────────│  линия цвета программы
│                                              │
│                     тело                     │  своё для каждого окна
│                                              │
│                      [ Отмена ] [ Выбрать ]  │  dialog_buttons()
└──────────────────────────────────────────────┘
```

| Средство | Что делает |
|---|---|
| `dark_titlebar(window)` | тёмный системный заголовок в Windows: над тёмным окном светлая, а при цветном оформлении синяя полоса выглядит как чужая деталь |
| `dialog_header(window, title, subtitle)` | шапка окна и тонкая линия цвета программы под ней — та же, что полоса хода работы в главном окне |
| `dialog_buttons(parent, actions)` | ряд кнопок: одна ширина, главное действие последнее и накрашенное |
| `center_over(window, parent)` | окно открывается посреди программы, а не в углу экрана |

Правила, которые соблюдают все окна:

1. Заголовок окна — `«Ренеймер документов — что делаем»`. По панели задач
   видно, что окно принадлежит программе.
2. Шапка — строкой `Dialog.TLabel`, пояснение под ней — `Muted.TLabel`.
3. Тело занимает всё свободное место (`rowconfigure(..., weight=1)`).
4. Ряд кнопок прижат вправо, снизу и справа отступ `PAD_L`. Порядок один:
   сначала отказ, потом действие. Главное действие — `Accent.TButton`.
5. `Escape` закрывает окно без изменений, `Return` выполняет главное действие
   там, где это не мешает вводу.
6. Ширина кнопки — `BUTTON_WIDTH` или длина надписи плюс запас, если надпись
   длиннее. Обрезанная надпись на главной кнопке — не мелочь оформления:
   непонятно, что нажимаешь.

### Палитра и размеры

Цвета живут в одном словаре `COLORS`, отступы — в шкале `PAD_XS` (2), `PAD_S`
(6), `PAD_M` (10), `PAD_L` (16). Числа вроде `padding=14` в коде окна — ошибка:
они ломают общий ритм. Шрифты — `FONT_UI`, `FONT_UI_BOLD`, `FONT_SMALL`,
`FONT_SECTION`, `FONT_MONO`, `FONT_TITLE`.

| Роль цвета | Ключ | Где применяется |
|---|---|---|
| фон окна | `bg` | все окна и рамки |
| карточка | `panel` | предпросмотр, кнопки, заголовки таблиц |
| поле ввода | `field` | строки ввода и списки |
| основной цвет | `accent` | главные кнопки, линия под шапкой, выделение строки |
| готово / внимание / ошибка | `ok`, `warn`, `error` | состояния строк и значок готовности |

### Подсказки

`Tooltip` появляется через `DELAY_MS` (500 мс) наведения без нажатия, держится
`SHOW_MS` (4 с) и исчезает. Подсказка обязана помогать, а не загораживать
соседние кнопки, пока к ним ведут мышь.

### Логика — вне окна

`gui.py` собирает виджеты и вызывает бизнес-логику. Всё, что можно посчитать
без Tkinter, живёт в `presentation.py`, `preview.py`, `browsing.py` и
`reveal.py` — там же это и проверяется тестами. Тесты самих окон лежат в
`tests/gui/` и пропускаются там, где графической подсистемы нет.

## 6. Как строится имя

```text
факты (Field с evidence)
      ↓  naming/builder.build_segments      выбор сегментов по категории
      ↓  naming/sanitizer.assemble_filename сборка с учётом длины
      ↓  naming/review.review_name          независимая перечитка
      ↓  naming/collision.resolve_collision свободное имя в каталоге
предложенное имя
```

**Первый проход** (`builder.py`) знает, откуда что взялось, и собирает имя по
образцу `Вид_Участники_Номер_Дата`. Порядок и формат даты задаются
настройками `naming.order` и `naming.date_format`. Если исходное имя
осмысленное (`is_meaningful_stem`), оно сохраняется и дополняется только
датой (`build_preserved_name`).

**Второй проход** (`review.py`) не знает, как имя собиралось: он видит готовую
строку и сегменты. Поэтому он ловит ошибки первого — две даты, повтор одного
и того же слова, случайное число, дату, принятую за номер, строчную букву в
начале. Мелочь исправляется, при серьёзном замечании (`is_blocking`) имя не
предлагается вовсе и файл получает `NAME_REVIEW_FAILED`.

**Санитизация** (`sanitizer.py`): удаляются запрещённые в Windows символы
`< > : " / \ | ? *` и control-символы, отбрасываются точки и пробелы в конце,
проверяются зарезервированные имена (`CON`, `PRN`, `NUL`, `COM1`…), длина
ограничивается `naming.max_filename_length`. При сокращении первыми уходят
второстепенные сегменты, а не идентификаторы.

**Коллизии** (`collision.py`): имя проверяется без учёта регистра, свободное
подбирается суффиксом `__02`, `__03`. Проверка повторяется непосредственно
перед переименованием.

## 7. Уверенность

`analysis.compute_confidence` складывает взвешенную оценку:

| Слагаемое | Вес |
|---|---|
| вид документа | 3.0 |
| дата документа | 3.0 |
| номер документа | 2.0 |
| номер дела | 2.0 |
| предмет | 2.0 из метаданных, иначе 1.0 |
| ключевое лицо | 1.0 |
| организация | 1.0 |

Надёжность источника — множитель: значение от модели считается с
коэффициентом 0.9, из файловой системы — 0.5. Самооценка модели никогда не
является единственным основанием. Диагностические состояния
(`ENCODING_UNCERTAIN` и подобные) дают штраф.

Фото, видео и аудио оцениваются отдельно (`media_confidence`), но снимок
документа оценивается как документ.

Порог автоматического переименования — `naming.confidence_threshold` (0.88),
для папок ниже — `naming.folder_confidence_threshold` (0.72): у папки нет
своего текста, зато повторение одного человека или номера дела в нескольких
файлах — сильный довод, а переименование папки откатывается вместе с сессией.

## 8. Локальная модель

Модель — не источник фактов, а способ разрешить неоднозначность.

- запускается через локальный `llama-cli` списком аргументов, без
  `llama-server`, без HTTP даже на localhost, без загрузки моделей;
- получает не документ целиком, а компактный INPUT: имя файла, тип,
  метаданные, заголовок, кандидаты дат, номеров, ФИО и организаций, начало и
  конец текста;
- работает с русским текстом в Unicode без транслитерации; ответ для
  русского документа обязан остаться русским;
- отвечает только JSON; парсер проверяет схему, отбрасывает неизвестные поля;
- каждое значение проверяется на присутствие в INPUT
  (`validator.evidence_supported`); не подтверждённое отбрасывается со
  статусом `AI_EVIDENCE_REJECTED`;
- если модели нет, работают правила, а файл получает `MODEL_NOT_FOUND` —
  скачивания не происходит.

## 9. Безопасность

**Границы доверия.** Недоверенный вход — пользовательские файлы, имена и пути.
Недоверенный выход — JSON локальной модели. Обе границы имеют явную проверку:
`readers/*` с лимитами и безопасными парсерами, `ai/validator.py` со сверкой
по INPUT.

**Недоверенный вход** (раздел 54 ТЗ): макросы не исполняются, JavaScript не
исполняется, XML читается `defusedxml`, архивы не распаковываются,
распаковка ограничена по объёму, объём текста и число страниц OCR ограничены,
у subprocess есть timeout.

**Subprocess** — только `security/subprocess_safe.run_tool`: список
аргументов, `shell=False`, timeout, `check=False`, без консольного окна.
Строковая конкатенация команд запрещена.

**Сеть.** В `src/docrenamer` не должно быть ни `requests`, ни `httpx`, ни
`urllib.request`, ни литералов URL. Это проверяет
`security/offline_guard.py` и тест `tests/safety/test_source_audit.py` —
незаметно внести такой код не получится.

**Временные данные** живут в `runtime_temp/<session-id>/` и удаляются;
`temp_cleanup.purge` откажется удалять что-либо за пределами `runtime_temp`.

## 10. Конфигурация

`config.py` читает `config/config.json`, проверяет типы и диапазоны и даёт
`Config` — набор dataclass'ов (`AIConfig`, `OCRConfig`, `NamingConfig`,
`MediaConfig`, `ArchivesConfig`, `LimitsConfig`, `UpdateConfig`,
`LearningConfig`). Неверное значение даёт `ConfigError` с русским текстом.

- `Config.fingerprint()` — отпечаток настроек, попадает в manifest: по нему
  видно, при каких настройках была выполнена операция;
- `write_json_atomic` — запись служебного файла через `.tmp` → `flush` →
  `fsync` → `os.replace`. На пользовательские файлы это не распространяется;
- `load_document_types` — словарь видов документов; расширяется правкой
  `config/document_types.json` без пересборки.

Полный список полей со значениями по умолчанию — в
[руководстве пользователя](РУКОВОДСТВО.md#13-настройки).

## 11. Журналы и manifest

| Файл | Что внутри |
|---|---|
| `logs/rename_log_*.txt` | человекочитаемый журнал: файл, предложение, вид, дата, уверенность, SHA-256 до и после, итог |
| `manifests/rename_manifest_*.json` | сессия, версия, отпечаток настроек, сведения о модели, по каждой операции — пути, имена, SHA-256, размер, время, тип, анализ, evidence, уверенность, статус |
| `logs/scrub-*.json` | что снято при очистке метаданных и что осталось |
| `logs/learning_report.json` | обезличенная статистика работы алгоритма имён |

Manifest пишется **инкрементально**: после каждой удачной операции. Поэтому
после аварии `find_incomplete_sessions` находит незавершённую сессию, а
`recover_from_journal` собирает из журнала полноценный документ — откат
возможен даже после сбоя.

Всё пишется в UTF-8 с `ensure_ascii=False`: кириллица в manifest хранится как
кириллица.

## 13. Тесты

```text
tests/
├── conftest.py      общие фикстуры: app_paths, config, workdir, russian_files
├── fixtures/        синтетические файлы: builders.py собирает PDF, JPEG, DOCX и прочее
├── unit/            модули по отдельности
├── integration/     сквозные сценарии: CLI, полный цикл, разбор корпуса
├── safety/          инварианты файловой системы, офлайн, аудит исходников
└── gui/             окно: дерево, окно выбора папки, подсказки
```

Маркеры (`pyproject.toml`):

| Маркер | Смысл |
|---|---|
| `safety` | инварианты безопасности файловой системы |
| `offline` | работа без сети |
| `integration` | сквозные сценарии |
| `requires_tesseract`, `requires_exiftool`, `requires_ffprobe`, `requires_model` | требуют внешний компонент, иначе пропускаются |

Обязательные правила:

- **любая мутация файловой системы сопровождается тестом** (правило 14
  `AGENTS.md`);
- изменение, сделанное по отчёту об именах, сопровождается тестом на этот
  случай: отчёт говорит «часто правят», тест фиксирует, как должно быть;
- реальные конфиденциальные материалы в тестах не используются — только
  синтетические фикстуры;
- для каждого теста переименования проверяется, что `sha256` и `size` до и
  после совпадают.

**Release gate раздела 95 ТЗ** — `tests/safety/test_russian_release_gate.py`.
Выпуск запрещён, если хоть один пункт не пройден: русские имена файлов,
совпадение SHA-256 на кириллических именах, отсутствие молчаливого mojibake,
недоверие к плохому текстовому слою PDF, локальный OCR `rus+eng`, кириллица
в JSON manifest и в журналах, отсутствие `errors="ignore"` в любом fallback
декодирования.

## 15. Рецепты

### Добавить формат

1. написать reader в `readers/`, вернуть `ReadResult`; открывать файл только
   на чтение, соблюдать лимиты из `context_limits`;
2. зарегистрировать его в сборке конвейера (`analysis.build_analyzer`) по
   типу или по категории;
3. добавить сигнатуру в `file_signature.py`, если тип определяется по
   содержимому;
4. положить синтетическую фикстуру в `tests/fixtures/builders.py` и написать
   тест в `tests/unit/test_readers.py`;
5. дописать строку в support matrix `ARCHITECTURE.md` и в таблицу форматов
   `README.md`.

### Добавить вид документа

Правится `config/document_types.json`, пересборка не нужна:

```json
{
  "canonical_name": "Соглашение о расторжении",
  "aliases": ["соглашение о расторжении договора"],
  "markers": ["СОГЛАШЕНИЕ О РАСТОРЖЕНИИ"],
  "priority": 10,
  "filename_abbreviation": "Соглашение_о_расторжении"
}
```

Затем — тест в `tests/unit/test_extractors.py`, что файл с таким текстом
получает нужный вид.

### Добавить факт в имя

1. extractor в `extractors/` возвращает `Candidate` с контекстом — это и есть
   evidence;
2. `analysis.Pipeline.enrich` кладёт значение в `FileAnalysis` как `Field` с
   `source` и `evidence`;
3. `naming/builder.build_segments` решает, попадает ли значение в имя;
4. `naming/review.py` учит второй проход не считать новый сегмент ошибкой;
5. тесты: на extractor, на построение имени, на самопроверку имени.

### Добавить поле конфигурации

1. поле в нужный dataclass `config.py` со значением по умолчанию и
   комментарием, зачем оно;
2. разбор в `from_dict` с проверкой типа;
3. значение в `config/config.json`;
4. строку в таблицу настроек `docs/РУКОВОДСТВО.md`;
5. тест в `tests/unit/test_hashing_config.py` или рядом.

### Добавить элемент интерфейса

Логику размещать не в `gui.py`, а в `presentation.py`, `preview.py` или
`browsing.py` — их можно проверить там, где Tkinter недоступен. В `gui.py`
остаётся только сборка виджетов. Тест на логику — в `tests/unit/`, тест на
окно — в `tests/gui/` с `pytest.importorskip("tkinter")`.

## 16. Ограничения среды разработки

Разработка ведётся на Linux, поэтому часть проверок выполняется только на
целевой платформе:

- **графический интерфейс.** Если в системе нет `tkinter`, тесты `tests/gui/`
  пропускаются целиком. На Debian и Ubuntu он ставится пакетом
  `python3-tk`; в Python для Windows входит в состав. Без него проверяются
  только `presentation.py`, `preview.py`, `browsing.py`;
- **сборка `.exe`.** PyInstaller не поддерживает кросс-компиляцию:
  исполняемый файл Windows собирается только на Windows. На Linux
  проверяется сама спецификация сборки и состав данных;
- **внешние программы.** Tesseract, ExifTool, ffprobe, llama.cpp в среде
  разработки обычно отсутствуют. Их поведение покрыто контрактными тестами с
  подставными реализациями и проверкой кодов `OCR_ENGINE_NOT_FOUND` и
  `MODEL_NOT_FOUND`;
- **запуск с USB и из произвольного каталога** проверяется вручную перед
  выпуском.
